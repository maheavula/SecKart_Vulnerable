## 2. Security Challenge & Remediation Matrix

| Issue Name | Difficulty Tier | OWASP Category | How to Reproduce in Website | 3 Business & Security Impacts | 3 Secure Coding Remediations |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **Open Swagger / OpenAPI Endpoint** | Tier 1 (Easy) | A05:2021 – Security Misconfiguration / API9:2023 – Improper Assets Management | Navigate to `/api/docs` in your browser or HTTP client to view internal OpenAPI schema exposing administrative endpoints. | 1. Exposes unlisted administrative API endpoints.<br>2. Discloses parameter types and database structures.<br>3. Speeds up attacker endpoint discovery. | 1. Disable documentation endpoints in production environments.<br>2. Require administrative authentication on documentation routes.<br>3. Strip internal maintenance routes from public API specifications. |
| **Verbose Error Stack Traces in API Responses** | Tier 1 (Easy) | A05:2021 – Security Misconfiguration | Send a POST request to `/api/debug/error`. Observe the HTTP 500 response containing `stack`, `internalCode`, and system file paths. | 1. Discloses server file directory structures and framework versions.<br>2. Pinpoints exact code lines and vulnerable methods to attackers.<br>3. Violates compliance standards like PCI-DSS and SOC2. | 1. Implement global error-handling middleware returning generic messages.<br>2. Log full stack traces internally to secure log systems rather than HTTP responses.<br>3. Restrict verbose diagnostic flags to local development builds. |
| **Non-Enforced Password Policy on Registration** | Tier 1 (Easy) | A07:2021 – Identification and Authentication Failures | Go to Create Account, submit a 1-character password (e.g. `"1"`), or send POST to `/api/auth/quick-signup`. The server accepts the weak credential. | 1. User accounts become vulnerable to credential stuffing and brute-forcing.<br>2. Automated bots easily register spam accounts.<br>3. Compromised user accounts damage platform reputation. | 1. Enforce length and complexity requirements (minimum 12 characters, mixed case, numbers, symbols).<br>2. Reject passwords found in public breach databases.<br>3. Implement server-side validation feedback before account creation. |
| **Unvalidated URL Redirect Parameter (Open Redirect)** | Tier 1 (Easy) | A01:2021 – Broken Access Control / API8:2023 – Security Misconfiguration | Navigate to `/api/auth/redirect?url=https://evil.com` in your browser. The browser automatically redirects to the external domain `evil.com`. | 1. Enables realistic phishing campaigns using legitimate domain links.<br>2. Risks authorization code or token leakage via URL fragments.<br>3. Causes domain reputation degradation by search engines. | 1. Restrict redirect targets to relative URL paths starting with `/`.<br>2. Maintain a strict server-side allowlist of permitted destination domains.<br>3. Use internal lookup keys mapped to fixed internal routes instead of accepting arbitrary URLs. |
| **Pre-Seeded Default Administrative Credentials** | Tier 1 (Easy) | A07:2021 – Identification and Authentication Failures | Fetch `/api/config/defaults` or inspect configuration files to locate default credentials `admin:admin123`. Submit these credentials at the sign-in prompt. | 1. Grants immediate administrative control to attackers upon deployment.<br>2. Risks unauthorized exfiltration or deletion of store data.<br>3. Allows non-privileged users to escalate privileges. | 1. Inject initial credentials via environment variables during deployment.<br>2. Force mandatory password changes upon first administrative login.<br>3. Generate single-use random setup tokens during initial boot. |
| **Insecure Direct Object Reference (IDOR) on Order Retrieval** | Tier 2 (Medium) | A01:2021 – Broken Access Control / API1:2023 – Broken Object Level Authorization | Sign in as Customer A, note another user's order ID (e.g. `SK-3001`), and fetch `GET /api/orders/lookup/SK-3001`. The endpoint returns full order details regardless of owner. | 1. Mass exposure of customer names, delivery addresses, and purchase histories.<br>2. Severe financial penalties for privacy regulation non-compliance.<br>3. Competitors can scrape order frequencies and sales metrics. | 1. Enforce server-side checks verifying that the requested object belongs to the authenticated user.<br>2. Scope database queries to filter by both object ID and current user ID.<br>3. Replace sequential IDs with unguessable UUIDs. |
| **Unvalidated User Scope on Cart Update** | Tier 2 (Medium) | A01:2021 – Broken Access Control / API3:2023 – Broken Object Property Level Authorization | Send POST to `/api/cart/update` with a payload containing `userId: "victim_id"` and an array of items. The cart for `victim_id` is modified without authorization. | 1. Attackers can clear or tamper with shopping cart items of active users.<br>2. Forces high-value unwanted items into victim carts before checkout.<br>3. Causes session state cross-contamination. | 1. Bind cart operations strictly to the user identity extracted from the authenticated session token.<br>2. Reject or ignore client-supplied user identity keys in request bodies.<br>3. Implement automated tests verifying user scope enforcement. |
| **Unescaped User Comments Rendering (Stored XSS)** | Tier 2 (Medium) | A03:2021 – Injection | Submit a product review containing `<script>alert(document.cookie)</script>` or send POST to `/api/reviews/submit`. View the review page to see the script execute in the browser. | 1. Allows attackers to steal session cookies and hijack user sessions.<br>2. Enables DOM defacement and display of fake login forms.<br>3. Permits keylogging of sensitive user input. | 1. Sanitize and HTML-entity-encode all user input before storage and rendering.<br>2. Use safe DOM rendering APIs like `textContent` instead of `innerHTML`.<br>3. Enforce a Content Security Policy (CSP) blocking inline script execution. |
| **Flagged Dependencies in package.json** | Tier 2 (Medium) | A06:2021 – Vulnerable and Outdated Components | Open `package.json` or run `npm audit` in the root directory. Identify outdated packages with known security vulnerabilities (e.g. `lodash@4.17.15`, `jsonwebtoken@8.5.1`, `express@4.16.0`). | 1. Outdated utility libraries enable prototype pollution leading to remote code execution.<br>2. Older JWT libraries permit algorithm confusion and authentication bypass.<br>3. Automated scanners target published component vulnerabilities. | 1. Integrate automated dependency vulnerability scans into CI/CD pipelines.<br>2. Pin exact package versions and enable automated dependency update PRs.<br>3. Audit third-party packages for malicious code before installation. |
| **Missing Quantity Validation on Checkout** | Tier 2 (Medium) | A04:2021 – Insecure Design / API6:2023 – Unrestricted Access to Sensitive Business Flows | Send POST to `/api/checkout/legacy` with item `quantity: -5`. The total subtotal becomes negative or zero, allowing free orders or artificial credits. | 1. Users obtain items for free or generate negative cart balances.<br>2. Negative quantities corrupt seller inventory records.<br>3. Direct financial loss due to unauthorized credit generation. | 1. Validate that all item quantities are positive integers within a reasonable range (1–10).<br>2. Use strict request schema validation for checkout payloads.<br>3. Recalculate order totals strictly from server-side database rates and validated item counts. |
| **Missing Role-Based Authorization Check on Admin Middleware** | Tier 3 (Hard) | A01:2021 – Broken Access Control / API5:2023 – Broken Function Level Authorization | Sign in as a standard Customer, obtain a session cookie, and send PATCH to `/api/admin/system-settings`. The settings are updated because the endpoint checks authentication but omits role verification. | 1. Standard customers can modify platform settings, store name, or maintenance status.<br>2. Unauthorized users can lock down the store by forcing maintenance mode.<br>3. Standard users can escalate privileges to Seller or Admin. | 1. Apply middleware verifying that the authenticated user possesses the specific required role (Admin).<br>2. Implement a centralized Access Control List (ACL) for administrative endpoints.<br>3. Adopt a default-deny policy for all administrative routes. |
| **Exposed Sandbox Test API Keys in Client-Side Bundles** | Tier 3 (Hard) | A05:2021 – Security Misconfiguration | Inspect `app.js` or client JavaScript bundles in browser DevTools. Search for hardcoded API keys such as `STRIPE_TEST_SECRET_KEY = "sk_test_..."` or `AWS_SECRET_ACCESS_KEY`. | 1. Third parties can use exposed keys to process unauthorized charges or refunds.<br>2. Exposed cloud keys risk data exfiltration from cloud storage.<br>3. Payment processors may suspend merchant accounts for secret key leaks. | 1. Keep secret API keys strictly on backend servers in environment variables.<br>2. Expose only non-sensitive publishable keys to browser code.<br>3. Use automated secret scanning tools in pre-commit hooks to prevent key leaks. |
| **Unvalidated Discount Calculation Logic** | Tier 3 (Hard) | A04:2021 – Insecure Design / API6:2023 – Unrestricted Access to Sensitive Business Flows | Send POST to `/api/checkout/apply-discounts` passing an array of duplicate codes `["SAVE20", "SAVE20", "SAVE20", "SAVE20", "SAVE20", "SAVE20"]`. The discount exceeds 100%, driving the total below zero. | 1. Produces negative order totals and invalid payouts.<br>2. Users stack multiple promotional offers unintended by business rules.<br>3. Causes rapid inventory depletion by unauthorized resellers. | 1. Restrict orders to at most one valid public promotion code.<br>2. Enforce a minimum total floor ensuring order costs cannot drop below zero.<br>3. Track and audit coupon redemptions on a per-user basis. |
| **Deterministic Timestamp-Based Password Reset Token Generation** | Tier 3 (Hard) | A07:2021 – Identification and Authentication Failures | Send POST to `/api/auth/reset-token`. Inspect the generated reset token and observe it is an MD5 hash of `Date.now() + userId`, allowing offline token prediction. | 1. Attackers can guess reset tokens for target accounts and perform account takeovers.<br>2. Automated scripts can hijack accounts by brute-forcing token timestamp windows.<br>3. Completely bypasses password-based authentication. | 1. Generate reset tokens using cryptographically secure random number generators (CSPRNG).<br>2. Store only salted SHA-256 hashes of reset tokens in database storage.<br>3. Set short expiration windows (15 minutes) and invalidate tokens after single use. |
| **Hardcoded Fallback JWT Secret in Configuration** | Tier 3 (Hard) | A02:2021 – Cryptographic Failures / A05:2021 – Security Misconfiguration | Send POST to `/api/auth/jwt-verify` without setting the `JWT_SECRET` environment variable. The response confirms authentication verified using the default fallback secret `"supersecret123"`. | 1. Attackers can forge valid JWT signatures for any user ID or administrative role.<br>2. Completely bypasses user authentication across all protected API routes.<br>3. Forged tokens remain valid until expiration without server detection. | 1. Fail closed on startup if `JWT_SECRET` is missing or shorter than 32 characters.<br>2. Use asymmetric key pairs (RS256) for signing and verifying tokens.<br>3. Implement automated configuration verification tests before application startup. |
